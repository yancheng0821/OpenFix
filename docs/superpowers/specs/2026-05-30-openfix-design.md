# OpenFix 设计稿

- **日期**：2026-05-30
- **状态**：设计已通过，待用户复审 → 进入实现计划
- **一句话**：一个由"深度排查 agent"驱动的傻瓜化 macOS 桌面 App——用户说一句话（"我连不上网"），它自己查、自己修、自己验证，全程不打扰。

---

## 1. 背景与动机

用户（本项目作者，开发者）发现自己遇到电脑问题时，会直接找 Claude Code / Codex 去排查，因为很多问题确实复杂、人肉根本查不明白。这暴露了一个真实需求：**有大量"电脑/网络坏了但搞不定"的人，现在没有趁手的工具**。

竞品现状：

| | 能修复杂问题 | 普通人能用 |
|---|---|---|
| 腾讯 Marvis（消费向 OS 级助手） | ❌ 浅，靠写死脚本 | ✅ |
| Claude Code / Codex（coding agent） | ✅ 深 | ❌ 要会写 prompt、没安全护栏、要盯着 |
| **OpenFix** | ✅ **像 CC 一样深挖** | ✅ **一句话搞定、可回滚** |

Marvis 2026-05-20 上线，1 主 +5 副多智能体、零配置、端云双模式、敏感操作硬确认，但其系统运维能力（Computer Agent）只做 C 盘清理、电池检测、网络故障修复等浅层、脚本化的事，修不了复杂问题。Claude Code/Codex 够深，但不是为"修电脑"设计的，普通人用不了。

## 2. 差异化与护城河

护城河只立在"**受众用不了 coding agent**"的地方 = **普通人 / 非开发的电脑与网络问题**。在这块市场里，coding agent 的受众不重叠（普通人装不了也不会用），唯一对手 Marvis 又太浅；OpenFix 靠"像 Claude Code 一样真能深挖、真能修好"碾压它的浅。

四个差异点同时落在交互模型里：

1. **深挖**——像 Claude Code 那样真去调查（跑命令、读配置/日志、网络探测、推理），而非写死脚本
2. **一句话搞定**——普通人零参与，说一句话就完事
3. **安全**——只读默认无限、写操作可回滚、失败自动还原（Claude Code 不会自动存档+复测+回滚）
4. **可验证**——修完自动复测，"真修好了"看得见

**明确不做：开发环境问题（多版本/依赖/PATH 等）**。那里 Claude Code 已经赢了，没有护城河。

## 3. 目标用户

- **主目标**：普通人 / 非技术用户，遇到电脑·网络问题完全搞不定的人
- **次目标**：开发者遇到的"非开发"电脑问题（用 Claude Code 修 WiFi 能用但很别扭）
- **非目标**：开发环境 / 写代码相关问题

## 4. 范围

### v1（=M1 完成线）
- **平台**：仅 macOS（作者可 dogfood）
- **完成线**：Core 引擎 + **网络诊断包(A)** 在 macOS 端到端跑通
- **A 覆盖**：WiFi 有信号但没网 / 某网站·App 打不开 / 网速异常 / 代理·DNS 配置 / 端口占用 等

### 明确不在 v1
- Windows 平台
- 软件/系统包(B) 的完整深度（B 是 A 之后的下一个包）
- 本地模型 / 离线模式 / 普通人换模型 UI
- 普通人的 token 付费方案（v1 只作者自己用、用自己的云端 key）

## 5. 架构

```
┌───────────────────────────────────────────────┐
│  Core 引擎（技能包共用）                          │
│  ┌─────────────┐  ┌──────────┐  ┌────────────┐  │
│  │ Agent Loop   │  │ 安全闸    │  │ 快照/回滚层 │  │
│  │ (自写薄loop) │  │ 分级确认  │  │ 改前存档    │  │
│  └─────────────┘  └──────────┘  └────────────┘  │
│  ┌─────────────┐  ┌──────────┐  ┌────────────┐  │
│  │ 工具层        │  │ 验证器    │  │ LLM Provider│  │
│  │ 只读/写 两类  │  │ 复测      │  │ (AI SDK,可换)│  │
│  └─────────────┘  └──────────┘  └────────────┘  │
└──────────────────────┬────────────────────────┘
        ┌──────────────┴──────────────┐
        │  技能包接口                   │
        │  {症状识别·诊断知识·专属工具·复测} │
        └──┬──────────────────────┬────┘
       网络包(A,v1)           软件/系统包(B,次)
                  │
          ┌───────▼────────┐
          │ GUI (React)     │ 一个输入框 + 进度 + "做了啥/一键还原"
          └────────────────┘
```

### 技术栈
- **Electron + React + TypeScript**，引擎跑在 main 进程，单语言单运行时
- **引擎 = Vercel AI SDK（模型无关 provider 层）+ 自写薄 agent loop + 工具/安全/快照/验证**
- 不用 Claude Agent SDK：它是 Anthropic-only，与"普通人要能换自己的模型"冲突

### 工程结构（pnpm monorepo，参考 MoonshotAI/kimi-code）
参考开源项目 **MoonshotAI/kimi-code**（MIT、TS 编程 agent，library-first：`agent-core` 引擎与 TUI 壳分离）的设计，采用同构的 monorepo：

```
openfix/
├── apps/
│   └── desktop/          Electron + React GUI（壳）
├── packages/
│   ├── core/             引擎：agent loop · 工具系统 · 安全 hooks · 快照/回滚 · 验证器 · LLM provider
│   └── skill-network/    网络诊断包(A)：症状·诊断知识·网络工具·复测
└── docs/
```
- **安全 = hooks-gating**：借鉴 kimi-code"在关键点 gate 风险工具调用"的 hook 模式——写操作工具调用前由安全 hook 拦截、判级、快照
- **技能包 = plugin 式**：每个包是一个 package，向 core 注册 {症状·诊断知识·工具·复测}
- 但 loop / 安全 / 快照 / 复测**自己写**（不依赖 kimi-code 的 agent-core），因为安全是命门、要 100% 自控

### 关键技术决策与理由
- **TS 而非 Python**：GUI 是 React(=JS/TS)，桌面 App 用 Electron（main 进程本就是 Node），引擎用 TS 即可同栈单运行时、无 sidecar；而且要打包成签名公证的消费品时，Python sidecar 需对每个内嵌二进制签名公证、体积暴涨，Node 引擎签名范围收敛。Python 只在需要其独占 ML 库或独立 CLI 时才更优——本项目两者都不需要。
- **内核 + 可插拔技能包**：A、B 共用同一内核，差异只在"诊断知识 + 专属工具"；顺手实现可扩展（以后加"打印机包"等都是同一机制）。实现顺序 A→B。

## 6. 核心交互与安全模型（命门）

普通人不想参与排查，只想"说一句话，你给我搞定"。因此默认**全自动、不打扰**。让"一句话搞定"变安全，靠的**不是频繁让用户确认，而是"可回滚 + 自动验证"**。

```
你说一句话："我连不上网" / "GitHub 打不开" / "电脑好卡"
   ↓
自动只读调查（不打扰，最多一行字滚动）           ← 永不改动
   ↓
自动修：每步写操作前，先自动快照当前配置
   ↓
自动复测验证：真的通了吗？
   ├ 通了   → "修好了 ✅" + "我改了 X / 一键还原"
   └ 没通/更糟 → 自动回滚到原样 → 换思路再来一轮
                实在搞不定 → 老实报告"我没修好，但没动坏你任何东西"
   ↓
（极少）真正不可逆的操作（如删你的文件）→ 才停下来弹一次硬确认
```

### 四条原则
1. **默认全自动、不打扰**——满足"一句话干完"
2. **安全 = 可回滚 + 自动验证 + 失败自动还原**，而非频繁确认
3. **只读永远自动；可逆写操作自动做（但先快照）；不可逆操作才硬确认**——v1 网络域里几乎所有操作都可逆，所以几乎永远是"一句话→搞定"
4. **事后透明**——不打断，但给"我做了啥 + 一键还原"，要信任的人能看，不想看的人无视

### 安全的硬约束
- **写操作工具必须自声明**：可逆性、如何快照、如何回滚、风险等级
- **"是否不可逆"不交给 LLM 裸判**，由工具声明 + 规则决定
- 不可逆操作绝不静默执行

## 7. 内核单元分解（各单一职责、可独立测）

| 单元 | 职责 | 依赖 |
|---|---|---|
| Agent Loop | 一句话 → 规划 → 调工具 → 迭代 → 收敛到"修好/修不好" | LLM Provider、工具层 |
| 工具层（只读） | 跑安全命令、读配置/日志、网络探测 | 系统 shell |
| 工具层（写） | 改配置/重启服务，**带快照+回滚+风险声明** | 快照层 |
| 安全闸 | 按风险分级放行 / 硬确认 | 工具的风险声明 |
| 快照/回滚层 | 改前存档、一键还原 | — |
| 验证器 | 重跑触发探测，判定是否真修好 | 技能包的复测方法 |
| 技能包接口 | 封装某域的 {症状识别·诊断知识·专属工具·复测方法} | 工具层 |
| LLM Provider | 模型无关接入，可换 key/厂商/本地 | Vercel AI SDK |
| GUI | 输入框 + 进度 + 还原抽屉 + 硬确认弹窗 | 引擎 IPC |

## 8. 数据流

```
用户一句话
 → Agent Loop：LLM 规划
 → 调只读工具调查（自动）
 → LLM 形成诊断 + 选定写操作
 → 安全闸：可逆? → 快照后自动执行  /  不可逆? → 硬确认
 → 执行写操作
 → 验证器复测
     ├ 成功 → 报告 + 提供"一键还原"入口
     └ 失败 → 快照回滚 → 带新线索再迭代（达迭代上限则回滚到初始 + 老实报告）
```

## 9. 错误处理与边界

- **LLM 判断错** → 靠"复测验证 + 失败自动回滚"兜底（整套安全的核心机制）
- **断网 → 云模型不可达**（headline 场景的硬伤）→ v1 已知限制：检测到模型不可达时优雅降级提示；完整本地模型留 M4
- **需要 sudo / 管理员权限** → 明确告知、一次授权；处理 macOS 权限 / TCC
- **复测反复失败** → 设迭代上限 → 回滚到初始状态 → 老实报告"没修好也没搞坏"
- **不可逆操作** → 硬确认，绝不静默执行

## 10. 测试策略（改系统状态的工具最难测）

- **端到端**：用 VM / 一次性容器 + 预置"坏环境" fixtures（故意造 DNS 坏、代理错、端口占用等）跑真实修复
- **只读工具**：mock 命令输出做单元测试
- **快照/回滚层 + 验证器**：重点测——能否精确还原、能否准确判定修好
- **LLM loop**：录制场景做回归（不每次真打 LLM），关键路径少量真实 LLM 端到端

## 11. 里程碑

- **M1（= v1）**：Core 引擎骨架（loop + 工具层 + 安全闸 + 快照/回滚 + GUI 壳）+ 网络包(A) 在 macOS 端到端跑通
- **M2**：软件/系统包(B)
- **M3**：Windows 移植
- **M4**：本地模型 / 离线模式 / 普通人换模型 UI

## 12. 已知风险与已决开放项

### 已决
- **断网兜底**：v1 接受"网全断时跑不动、只做优雅提示"，本地模型留 M4
- **token 成本**：v1 只作者自己用、用自己的云端 key，暂不解决普通人付费

### 风险（需在实现早期验证）
- **macOS 权限 / 沙盒 / notarization** 对"跑系统命令 + 改网络配置"的限制——可能需要特殊 entitlements 或放弃沙盒，应在 M1 早期打通验证
- **危险操作的"不可逆判定"准确性**——安全命门，需严格的工具自声明 + 规则
- **断网时模型不可达**——headline 场景的结构性短板，M4 前一直存在

## 13. 决策记录（来自 brainstorming）

1. 定位：深挖(像 CC) + 普通人能用(像 Marvis) 的中间甜区
2. 用户：人人用同一个引导式 GUI，砍掉单独 Dev CLI
3. 切入点按"护城河"而非"问题域"选 → 锁定普通人非开发问题，dev-env 出局
4. 平台：macOS 先（可 dogfood）→ Windows 后
5. 栈：Electron + React + TypeScript（同栈单运行时 + 打包签名友好）
6. 引擎：Vercel AI SDK（模型无关）+ 自写薄 loop + 工具/安全/快照/验证
7. 架构：内核 + 可插拔技能包，实现顺序 A(网络)→B(软件/系统)
8. 交互/安全：全自动不打扰，安全靠"可回滚 + 自动验证 + 失败自动还原"，只读自动·可逆写自动快照·不可逆才硬确认
9. 名称：OpenFix（与 OpenClaw 同系，open + fix 直白说出"修好它"）
10. 框架：参考 MoonshotAI/kimi-code（MIT/TS/library-first）的设计——monorepo 分层、hooks-gating 安全、plugin 技能包、provider 无关；但引擎自写、不依赖其 agent-core（安全是命门要自控）。选 A（自建薄引擎 + kimi-code 当设计北极星），否决 B（建在 agent-core 上）与 C（fork）。
